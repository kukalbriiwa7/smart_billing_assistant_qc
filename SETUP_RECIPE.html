Smart Billing Assistant QC — Full Setup Recipe

This file explains, step by step, how to deploy your GitHub-hosted web app with passwordless email login and cloud data storage using Supabase.

Files in your bundle
  • index.html — the web app
  • supabase_setup.sql — database setup script
  • DEPLOYMENT_GUIDE.md — markdown deployment notes
  • SETUP_RECIPE.html — this visual step-by-step guide

1. What this architecture does

Your app frontend is hosted on GitHub Pages. Login and cloud storage are handled by Supabase.

  • Each surgeon enters their email
  • They receive a verification code by email
  • They log in without a password
  • Their cases are stored in the cloud under their own account
  • They can later log back in and see prior saved data

2. Create your Supabase project

Step 1
  1. Go to the Supabase website and create a free account.
  2. Create a new project.
  3. Choose a project name, database password, and region.
  4. Wait until the project finishes provisioning.

You only need one project for this app.

3. Create the database tables and policies

Step 2
  1. Open your Supabase dashboard.
  2. Go to SQL Editor.
  3. Create a new query.
  4. Open the file supabase_setup.sql from your bundle.
  5. Copy all of its contents.
  6. Paste it into the SQL Editor and run it.

That will create the required tables and row-level security rules so that each logged-in surgeon can access only their own data.

4. Turn on email OTP login

Step 3
  1. In Supabase, go to Authentication.
  2. Make sure email authentication is enabled.
  3. Open the email template for passwordless login / OTP login.
  4. Edit the template so it includes the token placeholder used by the app.
{{ .Token }}

This is the important part that makes Supabase send a verification code instead of only a magic link.

5. Configure your site URL

Step 4
  1. In Supabase, go to Authentication → URL Configuration.
  2. Set the Site URL to your GitHub Pages app URL.
  3. Add that same URL to the allowed redirect URLs if needed.

Example format:

https://kukalbriiwa7.github.io/smart_billing_assistant_qc/

6. Copy your Supabase project credentials

Step 5
  1. In Supabase, go to Project Settings → API.
  2. Copy the Project URL.
  3. Copy the anon public key.

You will paste these into the app code.

7. Edit index.html with your Supabase credentials

Step 6
  1. Open index.html in a code editor.
  2. Find the Supabase configuration block.
  3. Replace the placeholder values with your real project URL and anon key.

It will look similar to this:

const SUPABASE_CONFIG = {
  url: "https://YOUR-PROJECT.supabase.co",
  anonKey: "YOUR_PUBLIC_ANON_KEY"
};

Do not put your service role key into the frontend. Only use the anon public key.

8. Upload the files to your GitHub repository

Step 7
  1. Replace your old index.html in the GitHub repo with the new one from this bundle.
  2. Keep manifest.json and your icon files in the repo as before.
  3. Commit and push your changes.

Basic Git commands:

git add .
git commit -m "Add Supabase email OTP login and cloud sync"
git push origin main

9. Make sure GitHub Pages is enabled

Step 8
  1. In your GitHub repository, open Settings → Pages.
  2. Make sure the site is published from the correct branch, usually main.
  3. Make sure the published URL matches the Site URL you entered in Supabase.

Once GitHub finishes deployment, your app should be live.

10. Test the login flow

Step 9
  1. Open the live app URL on your phone or browser.
  2. Enter an email address.
  3. Request the verification code.
  4. Check the email inbox.
  5. Enter the received code in the app.
  6. Create a few test cases.
  7. Log out and log back in to verify the data reloads properly.

11. Recommended next improvements

  • Add a forgotten session recovery notice to the UI.
  • Add JSON/CSV export as a backup option.
  • Encrypt or avoid storing identifying patient information if this will be used in real clinical settings.
  • Add a surgeon profile page with their name, billing number, and hospital defaults.
  • Later, consider moving from a single-file app to separate files for better maintainability.

12. Important caution

This setup is good for a serious prototype and lightweight real-world use, but medical or billing-related data may raise privacy, institutional, and compliance issues depending on what is stored. Before real deployment in practice, review what patient data is being stored and whether it must be minimized, anonymized, or protected under institutional policy.
