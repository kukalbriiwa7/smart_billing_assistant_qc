ChirurgieQC — Guide de déploiement complet

Comment mettre l'application en ligne et configurer la connexion par courriel en moins de 20 minutes.

Ce que vous avez dans ce ZIP

  • index.html — L'application complète (interface + logique + base de données RAMQ)
  • manifest.json — Permet d'ajouter l'app à l'écran d'accueil iPhone
  • SETUP.html — Ce guide
Mode local sans serveur : L'app fonctionne immédiatement sans aucune configuration. Les données sont sauvegardées dans Safari sur votre appareil. Pour la connexion multi-appareils et la sauvegarde sur serveur, suivez les étapes ci-dessous.

Étape 1 — Créer votre base de données Supabase (gratuit)

Supabase est un service gratuit qui fournit une base de données PostgreSQL et un système d'authentification. Le plan gratuit inclut 50 000 utilisateurs actifs et 500 MB de base de données.

1
Créer un compte Supabase
Allez sur supabase.com → cliquez "Start your project" → inscrivez-vous avec votre courriel GitHub ou Google.
2
Créer un nouveau projet
Cliquez "New project" → donnez-lui un nom (ex: chirurgieqc) → choisissez un mot de passe fort pour la base de données → choisissez la région Canada (East) → cliquez "Create new project". Attendez ~2 minutes que le projet soit prêt.
3
Créer la table de données
Dans votre projet Supabase, cliquez sur SQL Editor (menu de gauche, icône terminale) → cliquez "New query" → copiez et collez le SQL suivant, puis cliquez "Run":
-- Table pour stocker les cas chirurgicaux
CREATE TABLE cases (
  id          TEXT PRIMARY KEY,
  user_id     UUID REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  date        DATE NOT NULL,
  payload     JSONB NOT NULL,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- Activer la sécurité par ligne (Row Level Security)
ALTER TABLE cases ENABLE ROW LEVEL SECURITY;

-- Politique: chaque chirurgien ne voit que ses propres cas
CREATE POLICY "Chirurgiens voient leurs propres cas"
  ON cases FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

-- Index pour accélérer les recherches par utilisateur
CREATE INDEX idx_cases_user_date ON cases(user_id, date DESC);
4
Configurer l'authentification par courriel
Dans Supabase, allez dans Authentication → Providers → Email. Vérifiez que "Enable Email provider" est activé. Assurez-vous que "Confirm email" est désactivé (pour simplifier la connexion OTP sans confirmation préalable). Courriel OTP est activé par défaut.
5
Récupérer vos clés API
Dans Supabase, allez dans Project Settings → API (icône engrenage en bas à gauche). Vous trouverez:
• Project URL — ressemble à https://abcxyzabc.supabase.co
• anon public key — une longue chaîne commençant par eyJ...

Étape 2 — Configurer l'application

Ouvrez le fichier index.html dans un éditeur de texte (Notepad sur Windows, TextEdit sur Mac en mode texte brut, ou VS Code). Cherchez ces deux lignes au début du code JavaScript :

const SUPABASE_URL      = 'VOTRE_SUPABASE_URL';
const SUPABASE_ANON_KEY = 'VOTRE_SUPABASE_ANON_KEY';

Remplacez VOTRE_SUPABASE_URL et VOTRE_SUPABASE_ANON_KEY par vos vraies valeurs de l'étape 1.5. Exemple :

const SUPABASE_URL      = 'https://abcxyzabc.supabase.co';
const SUPABASE_ANON_KEY = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3...';

Sauvegardez le fichier.

Étape 3 — Mettre l'app en ligne (GitHub Pages, gratuit)

1
Créer un compte GitHub
Allez sur github.com → "Sign up" → créez un compte gratuit.
2
Créer un dépôt
Connecté à GitHub, cliquez le bouton vert "New" (haut gauche) → nommez-le chirurgieqc → laissez-le en Public → cliquez "Create repository".
3
Téléverser les fichiers
Sur la page du dépôt, cliquez "uploading an existing file" → glissez index.html et manifest.json dans la zone → faites défiler vers le bas → cliquez "Commit changes".
4
Activer GitHub Pages
Dans votre dépôt → cliquez Settings (menu haut) → dans le menu gauche cliquez Pages → sous "Source" sélectionnez "Deploy from a branch" → choisissez la branche main → cliquez Save. Attendez 2-3 minutes.
5
Obtenir votre URL
Actualisez la page Settings → Pages. Votre URL apparaîtra : https://votrenom.github.io/chirurgieqc. C'est l'URL à partager avec les chirurgiens.

Étape 4 — Configurer Supabase pour accepter votre URL

Supabase a besoin de savoir d'où viennent les requêtes pour des raisons de sécurité.

1
Ajouter l'URL dans Supabase
Dans Supabase → Authentication → URL Configuration → dans "Site URL" entrez votre URL GitHub Pages : https://votrenom.github.io → dans "Redirect URLs" ajoutez : https://votrenom.github.io/chirurgieqc → cliquez Save.
2
Ajouter dans les paramètres CORS
Dans Supabase → Project Settings → API → section "CORS" → ajoutez https://votrenom.github.io dans les origines autorisées.

Étape 5 — Ajouter à l'écran d'accueil iPhone

1
Ouvrir dans Safari
Sur votre iPhone, ouvrez Safari (obligatoirement Safari, pas Chrome) et naviguez vers votre URL GitHub Pages.
2
Ajouter à l'écran d'accueil
Tapez le bouton de partage (carré avec flèche vers le haut, en bas de Safari) → faites défiler → tapez "Ajouter à l'écran d'accueil" → nommez-la "ChirurgieQC" → tapez Ajouter.

L'application s'ouvre maintenant en plein écran comme une app native, sans la barre Safari.

Comment fonctionne la connexion par courriel

Flux de connexion OTP (One-Time Password)
1. Le chirurgien entre son adresse courriel
2. Supabase envoie automatiquement un courriel avec un code à 6 chiffres (valide 10 minutes)
3. Le chirurgien entre le code dans l'app
4. L'app se connecte et charge les cas sauvegardés sur le serveur
5. La session est mémorisée — pas besoin de se reconnecter à chaque fois

Aucun mot de passe n'est jamais créé ni stocké. Chaque connexion utilise un nouveau code à usage unique.
⚠️ Important : Les courriels OTP peuvent parfois atterrir dans le dossier Indésirables/Spam la première fois. Demandez aux chirurgiens de vérifier leur dossier spam si le code n'arrive pas dans les 2 minutes. Après avoir marqué le courriel Supabase comme "non-spam", les futurs codes arriveront normalement.

Sécurité des données

  • Chaque chirurgien voit uniquement ses propres cas — la base de données est protégée par Row Level Security
  • Les données sont chiffrées en transit (HTTPS) et au repos dans Supabase
  • Supabase est hébergé sur AWS et est conforme SOC 2 Type II
  • Le plan gratuit Supabase est suffisant pour des dizaines de chirurgiens
  • Pour des exigences de conformité PIPEDA/LPRPDE plus strictes, Supabase offre des plans payants avec hébergement canadien dédié

Dépannage

Le code OTP ne fonctionne pas
Vérifiez que l'URL du site est bien configurée dans Supabase Authentication → URL Configuration. Le code expire après 10 minutes — demandez-en un nouveau.
Les données ne se synchronisent pas
Vérifiez que les valeurs SUPABASE_URL et SUPABASE_ANON_KEY dans index.html correspondent exactement à celles de votre projet Supabase. Vérifiez la console du navigateur (F12) pour les messages d'erreur.
L'app ne s'affiche pas sur GitHub Pages
GitHub Pages peut prendre jusqu'à 5 minutes la première fois. Vérifiez dans Settings → Pages que le statut indique "Your site is live at..."
Mode local vs mode connecté
Si Supabase n'est pas configuré, l'app fonctionne en mode local : les données sont stockées dans Safari sur l'appareil. Une bannière orange l'indique. Pour migrer les données locales vers le serveur, exportez d'abord en Excel depuis l'onglet Export.
